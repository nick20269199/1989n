# Branch A: 先秦诸子概论 — 合成

## 核心架构

先秦诸子的本质是**中国思想的第一次大规模专业化分工**：从巫史不分的王官之学分裂为各家学派，每派聚焦一个核心问题域。百家争鸣不是混乱而是**方法论多样性的系统工程**——每个学派都在回应同一些时代危机（礼崩乐坏/战争/治理失败），但给出了根本不同的诊断和处方。这种"同题异构"是理解中华思维DNA的关键。

## 关键机制

### 机制1: 百家争鸣 = 认知分工

**定义**: 诸子不是随机的思想集合，而是**问题域的专业化分工**：

| 学派 | 核心问题 | 回答 |
|------|---------|------|
| 儒家 | 如何重建秩序? | 复礼/仁政/教化 |
| 道家 | 如何合道? | 无为/自然/去智 |
| 墨家 | 如何利天下? | 兼爱/尚贤/节用 |
| 法家 | 如何强国? | 法治/耕战/刑赏 |
| 兵家 | 如何胜? | 全胜/不战/知彼 |
| 名家 | 如何正名? | 名实之辩/逻辑 |
| 阴阳家 | 如何顺天? | 五行/四时/大九州 |

**Agent映射**: 这=多Agent系统的分工模式——每个Agent有不同"第一问题"，不是对世界的不同答案而是不同的问题域。问题不同、答案自然不同。

### 机制2: 诸子互驳 = 对抗性验证

**定义**: 每家都是在反驳他家中建立自己的：

- 孟子辟杨墨 → 定义"儒"的边界
- 荀子非十二子 → 划清"道"与"蔽"的界限
- 庄子天下篇 → 以"道术"统摄诸子(一个宽容但高级的视角)

**Agent映射**: 对抗不是Bug而是Feature。多Agent系统不能只"协作"，需要制度化的互驳机制——每个Agent知道自己的盲点通过对手的批判来暴露。诸子互驳=最古老的Adversarial Review。

**设计推论**:
- 多Agent系统需要"异见Agent"（不是合作而是批判）
- 批判者不一定要"正确"，只要提出不同视角
- 被批判后的修正比独自优化更有效

### 机制3: 道术分裂 = 从统一到专业

**定义**: 《庄子·天下篇》说"道术将为天下裂"——从王官之学（统一的知识体系）分裂为诸子百家（专门化的知识领域）。

**Agent映射**: Agent知识的演化路径不是"从头构建"而是"从统一背景分化"——一个初始的"王官模型"（统一的框架预设）随着处理复杂任务而分化为专业模块。分裂不是退化而是适应复杂性的必然。

**发展序列**:
```
王官之学(统一) → 各守一偏(专业化) → 诸子互驳(对抗) → 新的综合(大一统/经学)
```

### 机制4: 思维原点 = Agent的第一框架

**定义**: 每家的出发点不是一个命题而是一个**基本隐喻/原初直觉**：

| 学派 | 思维原点 | 隐喻 |
|------|---------|------|
| 儒家 | 亲亲→仁 | 血缘亲情向外推 |
| 道家 | 道法自然 | 水/谷/牝 |
| 墨家 | 兼相爱交相利 | 工匠/几何/规矩 |
| 法家 | 好利恶害 | 权衡/度量/绳墨 |
| 兵家 | 兵者诡道 | 水/势/圆石 |

**Agent映射**: 每个Agent的"思维原点"=它的初始框架（初始化时的核心预设）。决定了它能看到的和看不到的。改变Agent的思维原点=改变它的一切输出。框架选择是最高阶设计决策。

### 机制5: 经子张力 = 保守与创新的动态

**定义**: 六经（《诗》《书》《礼》《乐》《易》《春秋》）是诸子共享的"经典池"，但每家对经典的诠释完全不同。儒家尊经、道家超经、法家改经、墨家造经。

**Agent映射**: 多Agent共享"记忆/数据/规则"（=经），但每个Agent有自己的诠释框架（=子）。完全一致的规则+多样化的诠释=系统既有统一性又有适应性。

| Agent层 | 对应经学 | 功能 |
|---------|---------|------|
| 共享协议/规则 | 六经 | 系统统一性 |
| 个体诠释框架 | 诸子 | 多样化适应 |
| 诠释冲突→修正 | 经学辩论 | 系统进化 |

### 机制6: 共识底层 = 共享的概念空间

**定义**: 诸子虽有分歧，但共享一套概念家族：道、天、心、性、命、气、理、阴阳、五行。分歧发生在共享框架内。

**Agent映射**: Agent之间要"有意义的争论"必须共享底层框架。争论是在框架内的争论，不是框架间的争论。如果要改变框架本身（范式转换）需要根本不同的机制。

**设计推论**:
- Agent的"分歧"如果是在共享框架内的→正常的多样性（健康）
- Agent的分歧涉及底层框架→需要中介/仲裁机制（风险）
- 共享概念空间不是消除分歧而是使分歧变得可理解

## Agent设计启示总结

先秦诸子给多Agent系统设计的关键洞见:

1. **多样性不是噪音**: 百家争鸣不是系统故障而是系统健康的表现。让Agent有不同的"第一问题"比让它们从不同角度回答同一问题更有效。
2. **对手是功能**: 为系统配置"批判Agent"（专门挑错的）比只配置"协作Agent"更鲁棒。
3. **框架分歧最深层**: Agent之间的不一致可能是因为框架不同而非数据不同。诊断分歧时先查框架，再查数据。
4. **共享经典+多样诠释**: 系统需要共享的底层协议（让沟通可能）和诠释自由度（让适应可能）。二者缺一不可。
5. **从统一到专业是演化必经**: 系统开始可以是一个统一的模型，随着复杂度增加自然分化。不要强求维持统一。
