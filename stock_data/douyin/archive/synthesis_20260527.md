## 一、九天Hector — Agent 架构原则

### 1. 五层安全防御模型
```
字符串拦截 → 正则过滤 → 白名单放行 → 独立AI审查 → 人工兜底
```
- 沙盒环境
- 断路器机制
- 双AI对抗策略
- 企业定制版本

**→ 系统映射**：当前系统只有 -7% 硬止损 + adversarial-review 单点防御。
可扩展为多层：数据采集层(白名单通道) → 清洗层(正则校验) → 分析层(独立审查) → 决策层(断路器) → 风控层(人工兜底)

### 2. Agent 核心三要素
```
大模型 + cmd命令行工具 + agent loop
```
**约束工作台四个维度**：
- 上下文管理 — 上下文不能无限膨胀
- 记忆管理 — 持久化 + 分层
- 工具接口 — 标准化接入
- 安全行为边界 — 显式约束规则

**→ 系统映射**：lead.py + 5 experts + grader 是一个 agent loop，但没有明确约束维度。
问题：每位 expert 独立采集数据后拼成大 prompt → 知识熵增。

### 3. 上下文膨胀两种架构
| 模式 | 说明 | 我们现状 |
|------|------|---------|
| SUB agents | 拆分子 agent 各管一段 | ✅ lead.py 分配任务给5 experts |
| agent teams | 多个 agent 协作，共享缓存 | ❌ 无共享缓存，expert 间数据重复拉取 |

**→ 系统映射**：expert1_tech 拉到的数据，expert2_money 要重新拉。应引入共享缓存层。

### 4. Hermes 体系（外部参考架构）
- 四层记忆系统（瞬时/短期/长期/持久）
- Skill 自生成/自进化（EGPA 进化引擎）
- 接入飞书机器人
- 工具集提示词经过精调，执行效率高

**→ 系统映射**：与我们设计的进化引擎方向一致（读书→蒸馏→注入循环）。
他的四层记忆系统可参考改进我们的 session_tracker + knowledge_db。

### 5. DeepSeek-V4 百万上下文
- 混合注意力架构
- 流形约束超连接
- Muon 优化器

**→ 系统映射**：百万上下文降低了 prompt 工程压力，但并不意味着不需要上下文管理。

## 二、清华姜学长 — 上下文工程

### 1. Agent 上下文膨胀 5 种解决方案

| 方案 | 我们的现状 | 优先级 |
|------|-----------|--------|
| **转移** — 上下文移到专门模块 | ❌ 所有 expert 共享大 prompt | P1 |
| **压缩** — 压缩会话历史 | ❌ 历史完整拼接 | P1 |
| **检索** — 从知识库查询 | ✅ knowledge_db 存在但未被 expert 自动调用 | P0 |
| **隔离** — 不同任务隔离上下文 | ✅ 每位 expert 独立函数 | - |
| **缓存** — 共享缓存省 Token | ❌ 每位 expert 独立拉数据 | P1 |

**核心 Gap**：5 位 expert 的 Prompt 加起来太长，每次调用烧 Token。
这五方案可直接指导 expert 管线优化。
