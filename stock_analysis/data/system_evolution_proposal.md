## 一、代码层面 — 最高ROI改进

### 1. 大文件拆解（⚠️ 高风险的长期手术）

**目标文件**: `daily_task.py` (2358行), `morning_brief.py` (954行)

**风险警告（用户补充）**:
- 38 个 .bat + Windows Task Scheduler 全部按 `python -m stock_analysis.daily_task closing_review` 注册，拆完所有 .bat 需同步修改，漏一个就是定时任务静默失败
- 各命令间隐式共享 Logger、路径常量、数据库连接、错误处理链，拆开易遗漏共享依赖
- 当前管线虽丑但已在生产稳定运行数月，拆分引入的新模块零实战验证

**Revised 策略**:

- 不动正在跑的代码，新功能直接独立模块 + 独立入口（如 `multi_angle_analysis.py` 模式）
- 等某命令需要大改时，趁那个窗口拆出来，不做主动拆除
- `morning_brief.py` 同理

### 2. 测试覆盖

- 现状: 7 个测试文件覆盖 ~90+ 源文件，全 unit test
- 缺口:
  - 无集成测试（数据源→分析→grader 全链路）
  - 无数据源 mock 测试（外部 API 挂了时的行为）
  - 无定时任务冒烟测试
- 目标: 聚焦 P0 管线（experts/ + 数据路由），不追求全面

### 3. 定时任务注册统一化

- 现状: 38 个 .bat 文件手工维护
- 方案: 维护 `tasks.json` 统一注册表（脚本/参数/调度/状态），.bat 自动生成
- 收益: 改路径/解释器不用改 38 处

## 二、架构层面 — 值得投资

### 4. 数据保鲜系统化

MarketPool 双 bug（日期格式不一致 + 未归一化）＝ 系统性痛点。

- 建立统一数据保鲜注册表: 每个数据产出声明"我是谁、谁生的、保质期多久"
- 读数据时自动检查生产者最后成功时间 + 时效
- `data_quality_gate.py` 已有雏形，扩展至全数据流

### 5. 专家管线扩展

当前 5 专家分析维度缺口：

- 筹码分布分析（股东人数变化、十大流通股东、人均持股）
- 产业链位置分析（在哪层、上游谁、下游景气）
- 微观结构分析（委比变化、撤单率、订单簿压力位）— 东方财富 Level-2

### 6. 决策回测闭环

当前决策输出后从不验证"上次说对没有":

- `decision_log` 表加 T+5 回测触发器: 预测 vs 实际
- 定期输出每个专家历史准确率 + 方向偏差
- 数据反馈到 grader 权重动态调整

## 三、研发创新

### 7. 多时间尺度认知架构

当前所有分析在"现在这个时刻"，决策需要三尺度：

| 尺度 | 当前状态 | 建议加强 |
|------|----------|----------|
| 日内 | intraday_report 已有 | 量价异动+资金突变实时告警 |
| 日间 | 复盘/晨报已有 | 趋势结构+模式识别 |
| 周/月 | **缺失** | 板块轮动迁徙、资金长周期流向、宏观因子切换 |

**高优先级**: 周度板块轮动监测 — 跟踪各板块资金流向周趋势，识别"资金正在从 AI 向半导体制造迁移"类早期信号。

### 8. 认知压缩 Level 3 — 跨品种模式匹配

- Level 1（当前实现）：日复盘 → 5 段摘要
- Level 2（weekly-audit 初现）：5 日连续摘要 → 周模式识别
- Level 3（新）："今天走势像历史上哪段？那次后来怎么走的？"

实现方式：不用 LLM 硬推理，SQLite 向量检索历史相似行情 + 当时决策 + 后来结果。

### 9. 自适应调度

当前定时任务固定时间触发。进化方向：

- 每任务记录耗时 + 成功率 + 数据新鲜度
- 某数据源连续失败 → 自动降频
- 盘中异动检测 → 临时加采
- 基于 `task_sentinel.py` 升级

## 五、不做的理由（同等重要的决定）

- **不引入 CI/CD**: Windows Task Scheduler + 单机环境，CI 的收益远小于配置成本
- **不换框架**: 当前 Python 原生 + CLI 模式足够灵活，引入 fastapi/click 等框架增加心智负担
- **不扩测试全量**: 对 ~90 文件追求全覆盖是浪费，聚焦 P0 管线即可
- **不做实时 Web 界面**: 飞书推送是信息密度/时效的最优解，Web 界面只多一层操作摩擦
