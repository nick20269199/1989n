# 交易认知生态 v2 — 四层六链闭环架构

> 2026-05-18 下午框架设计
> 核心理念：每次模型输出都是一次交易决策的空间映射，
> 方向/方式/轨迹/边际/逻辑 缺一不可。

---

## 总图

```
                    ┌─────────────────────────────────────────────┐
                    │             认知层生态圈                      │
                    │    (预测验证→偏差归因→信念修正→规则更新)        │
                    └──────────┬────────────────────┬────────────┘
                               │ 偏差报告            │ 规则/权重更新
             ┌─────────────────┤                    │
             │ 特征需求/质量阈值│                    │
             ▼                 ▼                    ▼
     ┌──────────────┐  ┌──────────────┐  ┌──────────────────┐
     │ 数据层生态圈   │  │ 分析层生态圈   │  │  执行层生态圈      │
     │ (采集→校验→    │→│ (路由→专家→   │→│  (仓位→下单→       │
     │  特征提取)     │  │  决策输出)    │  │  止损→记录)       │
     └──────────────┘  └──────────────┘  └──────────────────┘
           │                                    │
           └────────── 审计路径(U1) ─────────────┘
                      (认知层独立审计三层)
```

**单向箭头** = 主生产流程（数据→分析→执行）  
**虚线反馈** = 认知更新流程（事后修正）  
**审计路径** = 元层次分离（独立审计不共享推理上下文）

## 一、数据层生态圈

### 定位
**不是仓库，是筛子。** 把原始市场数据转化为带置信度的特征向量。

### 架构

```
原始API → [路由守卫] → [校验门] → [特征提取] → [特征存储]
  ├─ 腾讯API         ├─ null检测    ├─ R7信号
  ├─ Sina(备)        ├─ 异常值检测   ├─ 三倍量B点
  ├─ EastMoney       ├─ 时序断裂    ├─ 量价特征
  ├─ CLS新闻         ├─ 源延迟      ├─ 情绪特征
  └─ 大V雷达         └─ 置信度打分   └─ 资金流特征
                         │
                     [质量哨兵]
                     实时监控特征质量趋势
                     提前预警降级
```

### 输入/输出契约

| 项目 | 内容 |
|------|------|
| 输入 | 多源API原始响应 |
| 输出 | `FeaturePacket { features: [], confidence: 0~1, sources: [], timestamp }` |
| 门禁 | 无 confidence 的特征不发出 |
| 降级 | 主源故障 → 自动切备用源；全源故障 → 输出上一个已知状态 + 标记 stale |

### 内部状态

- **正常**：多源在线，特征置信度 > 0.9
- **降级**：单源故障，置信度 0.7~0.9
- **饥饿**：多源故障，置信度 < 0.7，标记输出为"推测态"
- **死亡**：全源故障 + 缓存过期，向上层发死亡信号

### 实施难度：★★☆☆☆（低）
- 已有 market_pool + 多源路由基础
- 需加：校验门（半天）+ 置信度打分（半天）+ 质量哨兵（半天）

## 二、分析层生态圈

### 定位
**不是报告生成器，是交易决策的"导航系统"。** 根据当前市场状态，路由到最合适的分析路径，产出结构化的决策包。

### 架构

```
FeaturePacket ─→ [市场状态分类器] ─→ [专家路由器]
                      │                     │
                  ┌────┴────┐        ┌──────┴──────┐
                  │ 趋势     │        │ 技术面专家   │
                  │ 震荡     │        │ 资金面专家   │
                  │ 结构性转变│        │ 基本面专家   │
                  │ 危机     │        │ 情绪面专家   │
                  └─────────┘        │ 宏观面专家   │
                                     └──────┬──────┘
                                            │ 各专家输出：
                                            │ 方向/方式/轨迹/边际/逻辑
                                            ▼
                                    [对抗审查门]
                                    (专家间交叉验证)
                                            │
                                    [置信度聚合器]
                                            │
                                    [决策包: DecisioPacket]
                                    含方向/方式/轨迹/边际/逻辑 + 置信度
```

### 市场状态分类器（核心）

| 状态 | 特征 | 对应策略 |
|------|------|---------|
| 趋势 | 价格沿均线运行，R7连续同向 | 趋势跟踪，高置信度可重仓 |
| 震荡 | 价格在区间内，成交量萎缩 | 区间交易，低置信度，降频 |
| 结构性转变 | 关键均线突破+放量+板块联动 | 全专家激活，高频率验证 |
| 危机 | 恐慌指数飙升，流动性枯竭 | 只出不进，执行层优先 |

### 专家路由原则

不全部激活 → MoE风格：
- 趋势状态 → 技术面专家权重最高，基本面次之
- 结构性转变 → 全专家激活，但对抗审查力度最大
- 震荡状态 → 资金面+情绪面为主，降频
- 危机状态 → 宏观面+资金面，只评估风险不评估收益

### 决策包输出格式

```json
{
  "symbol": "600236",
  "direction": "多/空/观望",        // 方向
  "method": "技术面+资金面",         // 方式（用了哪些专家）
  "trajectory": {                   // 轨迹（推理路径）
    "entry_zone": "7.2-7.4",
    "target": "8.0",
    "timeframe": "1-2周",
    "key_levels": [7.0, 7.6, 8.0]
  },
  "margin": {                       // 边际（什么条件下失效）
    "invalidated_if": "跌破7.0缩量",
    "confidence_decay": "持有超过3周未到目标→降级",
    "black_swan": "板块系统性杀跌→无条件撤"
  },
  "logic": {                        // 逻辑（因果假设）
    "because": "R7超大单连续3日净流入",
    "so": "机构在建仓",
    "if_wrong": "则机构在出货而非建仓，R7的假设（大单=建仓）不成立"
  },
  "confidence": 0.72,
  "state": "趋势",
  "timestamp": "2026-05-18T14:00:00"
}
```

**缺少任何一个字段 → 决策包被门禁拦截，不发出。**

### 实施难度：★★★★☆（高）
- 市场状态分类器：需定义量化规则（1天）
- 专家路由：每个专家需要独立 prompt + 工具链（3-5天）
- 对抗审查门：已有 adversarial-review skill 可接入（半天）
- 决策包格式化：输出约束（半天）
- **最难的部分**：让不同专家真正产生差异化分析，而不是互相附和

## 三、执行层生态圈

### 定位
**不是下单工具，是交易员的"制动系统"。** 把决策转化为执行，同时确保硬止损不能被推理绕过。

### 架构

```
DecisioPacket ─→ [仓位计算器] ─→ [下单引擎] ─→ [成交确认]
                      │              │              │
                  ┌────┴────┐    ┌────┴────┐    ┌────┴────┐
                  │ 凯利公式 │    │ 券商API  │    │ 三路同步 │
                  │ 风险预算 │    │ 备用通道  │    │ 持仓映射 │
                  │ 持有期   │    │ 拆单逻辑  │    │ 成本追踪 │
                  └─────────┘    └─────────┘    └──────────┘
                                          │
                                    [独立止损监控] ←─── 硬约束线程
                                    (定时扫描持仓,条件触发直接出单)
                                          │
                                    [偏差记录仪]
                                    (计划交易 vs 实际交易)
```

### 关键设计

**止损监控是独立线程** — 不经过分析层推理，不经过认知层审查：
- 启动时读取止损规则列表
- 运行时定时扫描持仓 + 当前价
- 触发条件 → 直接出单（通过券商API）
- 日志记录：何时触发、触发价、盈亏金额
- 监控线程崩溃 → 禁止新交易，直到重启确认

**仓位计算要回答"如果全错会怎样"**：
- 每笔最大亏损 = 账户总资金 × 固定比例（如 0.5%）
- 仓位 = 最大亏损 / (入场价 - 止损价)
- 不允许计算中出现 "不会跌到止损的" 这种乐观假设

### 三路同步（已有）

调仓时强制走 portfolio.json → concept_mapping.json → SQLite。不加新逻辑，只保证执行。

### 实施难度：★★★☆☆（中高）
- 仓位计算器：数学公式，简单（半天）
- 下单引擎：取决于券商API对接（1-3天）
- **独立止损监控线程**：这是技术难点，需要独立进程/线程 + 券商API权限（1天）
- 偏差记录仪：记录结构已定，追加字段即可（半天）
- 目前已有止损纪律文档 + 持仓数据同步，基础还可以

## 四、认知层生态圈

### 定位
**不是哲学复读机，是交易系统的"免疫系统"。** 从每次预测偏差中学习，修正规则、调整权重、进化认知。

### 架构

```
偏差记录 ─→ [预测验证器] ─→ [偏差归因] ─→ [信念更新引擎]
  │              │              │              │
  │         ┌────┴────┐    ┌────┴────┐    ┌────┴────┐
  │         │ 方向验证 │    │ 数据层?  │    │ 保护带修正│
  │         │ 幅度验证 │    │ 分析层?  │    │ 硬核审查  │
  │         │ 时序验证 │    │ 执行层?  │    │ 铰链审查  │
  │         │ 止损验证 │    │ 运气?    │    │ (U5分级) │
  │         └─────────┘    └─────────┘    └──────────┘
  │                                             │
  │                                        [模式矿机]
  │                                        (定期扫描偏差
  │                                         发现重复错误)
  │                                             │
  └──────────────────────┬──────────────────────┘
                         │ 输出:
                         │ → 分析层: 权重调整建议
                         │ → 执行层: 规则参数更新
                         │ → 数据层: 特征质量反馈
                         │ → 知识库: 新模式/反例沉淀
```

### 偏差归因规则

| 偏差类型 | 典型信号 | 归因 | 动作 |
|----------|---------|------|------|
| 方向反了 | 预测涨实际跌 | 分析层假设错误 | 检查R7/量价假设是否成立 |
| 幅度偏差 | 预测涨5%实际涨1% | 分析层高估动能 | 调整置信度-仓位映射 |
| 时序偏差 | 预测3天实现实际5天 | 分析层节奏错误 | 检查市场状态分类 |
| 执行偏差 | 计划买入但未执行 | 执行层障碍 | 检查券商API/操作纪律 |
| 止损跳过 | 触发止损但未出 | **严重违纪** | 触发U1审计，强制规则硬化 |

### U5 信念修正分级（核心机制）

| 层级 | 内容示例 | 修正条件 | 修正方式 |
|------|---------|---------|---------|
| 保护带 | "这只股票R7突破后可持有5天" | 单次偏差可调 | 自动调整参数 |
| 硬核 | "R7超大单流入=机构建仓" | 累积3次反例 | 分析层+认知层共同确认 |
| 铰链 | "市场总体反映真实交易" | 河流改道级事件 | 元认知最高审批+独立审计 |

### 实施难度：★★★★★（最高）
- 预测验证器：数据已有，逻辑简单（半天）
- 偏差归因：规则容易定义，但归因可能错误，需要审计（1天）
- **信念更新引擎**：真正的难点。U5分层修正规则如何编码？保护带可自动，硬核和铰链需要"审判会议"（分析层+认知层共同审议）
- **模式矿机**：从偏差数据中发现新模式（自然语言分析 + 统计模式匹配，2-3天）

## 五、闭环连接（六链）

### 链1：数据→分析（主生产）

```
FeaturePacket → [市场状态分类器] → 选专家 → DecisioPacket
```
- 实时性要求：秒级
- 失败影响：分析层无输入，不能生产决策包
- 降级策略：特征带 confidence < 0.7 → 分析层进入"推测模式"，只产"弱决策包"

### 链2：分析→执行（主生产）

```
DecisioPacket → [仓位计算器] → [下单引擎]
```
- 实时性要求：秒级
- 失败影响：有决策但不能执行，触发手动操作提示
- 降级策略：执行层故障 → 分析层继续运行但输出标记"仅参考"

### 链3：执行→认知（学习反馈）

```
执行记录 + 偏差数据 → [预测验证器]
```
- 实时性要求：盘后批量，非实时
- 失败影响：认知层收不到反馈，无法学习
- 降级策略：当天未完成 → 第二天优先处理

### 链4：认知→数据（特征优化）

```
信念更新 → [特征需求] → 数据层新增/调整特征
```
- 时效性：非实时，天级
- 内容："R7的XX特征权重下调"、"新增YY特征"
- 这是闭环的关键——认知层不只是分析错误，还能反向指导数据层关注什么

### 链5：认知→分析（权重调优）

```
偏差归因 → [专家权重调整] + [置信度校准]
```
- 时效性：非实时，天级（日复盘触发）
- 内容："技术面专家在趋势状态置信度不足，上调权重"
- 这是 MoE 路由的学习机制

### 链6：认知→执行（规则硬化）

```
偏差归因 → [止损参数修正] + [执行流程改进]
```
- 时效性：非实时，天级
- 内容："跌破EMA20还没止损→把止损规则从建议改为硬约束"
- 这是"交易员认知外化为系统规则"的通道

## 六、难度与成本评估

### 逐模块评估

| 模块 | 难度 | 工时估算 | 风险 | 是否可独立上线 |
|------|------|---------|------|--------------|
| 数据层校验门 | ★★☆ | 半天 | 低 | 可独立 |
| 数据层置信度打分 | ★★☆ | 半天 | 低 | 可独立 |
| 市场状态分类器 | ★★★ | 1天 | 中（规则需回测） | 可独立 |
| 专家路由框架 | ★★★ | 1天 | 中（架构设计需一次做对） | 依赖状态分类器 |
| 各专家内容 | ★★★ | 每个半天 | 中（质量取决于prompt） | 可逐个独立 |
| 对抗审查门 | ★★☆ | 半天 | 低 | 可独立 |
| 决策包格式化 | ★☆ | 2小时 | 低 | 可独立 |
| 仓位计算器 | ★★ | 半天 | 低 | 可独立 |
| 下单引擎 | ★★★★ | 1-3天 | 高（券商API对接） | 可独立但需测试 |
| 独立止损线程 | ★★★★ | 1天 | **最高**（资金安全） | 必须单独充分测试 |
| 三路同步强化 | ★☆ | 2小时 | 低 | 已有 |
| 预测验证器 | ★★ | 半天 | 低 | 可独立 |
| 偏差归因 | ★★★ | 1天 | 中（归因可能错） | 可独立 |
| 信念更新引擎 | ★★★★★ | 3-5天 | **高**（设计复杂） | 不可独立（依赖上面全部） |
| 模式矿机 | ★★★★ | 2-3天 | 中 | 可独立 |

### 失败成本和试错成本

这是一个必须诚实评估的部分。

**便宜的错误（可承受）：**
- 数据层校验规则设错了 → 调阈值就行，不会亏钱
- 市场状态分错了 → 产生低质量决策包，但你审核时能发现
- 专家权重调错了 → 多了一些噪音，不致命
- 决策包格式不对 → 改格式，零成本

**贵的错误（需要谨慎）：**
- 仓位计算器有bug → 可能多下或少下单 → **必须数学审计+单元测试**
- 止损线程没起或崩了 → 该止损没止损 → **必须写哨兵监控止损线程本身**
- 信念更新引擎自动改了硬核 → 错误的长期假设固定下来 → **U5审计层不能省**

**最贵的错误（不可逆）：**
- 下单引擎把买弄成卖、数量少个零 → **模拟盘先跑两周**
- 自动止损和券商API之间的连接可靠性 → **每次启动做一次空单测试**

### 建议实施顺序

```
Phase 0（2天、零资金风险）：
  数据层校验门 + 置信度打分
  → 决策包格式化（先手工填，不做路由）
  → 预测验证器（已有数据能跑）

Phase 1（3-4天、可模拟盘测试）：
  市场状态分类器
  → 专家路由 + 2-3个专家（技术面+资金面+宏观面）
  → 对抗审查门
  → 仓位计算器 + 模拟盘测试下单

Phase 2（3-5天、独立验证后上线）：
  独立止损线程（模拟盘跑1周）
  → 信念更新引擎（保护带级别先跑）
  → 模式矿机（读历史偏差数据）

Phase 3（持续）：
  剩余专家补全
  硬核/铰链修正上线（需累积证据）
  闭环自动运行
```

## 七、这个架构和上午的不同

上午的 `ecosystem_plan.md` 是**生产调度架构**：
- 什么时间点跑什么任务
- 数据怎么流动
- 飞书怎么推送

现在的 `v2` 是**交易认知架构**：
- 每次输出都回答"该不该交易、怎么交易"
- 五个维度缺一不可
- 从偏差中学习，循环进化

**两个要共存**：上午的管"什么时候做什么"，这个管"怎么做以及如何变好"。

## 八、一句话总结

四层不是数据/分析/执行/认知，是四个各自独立的生命体，通过六条链连接成闭环。

数据层负责"看到什么"（置信度），
分析层负责"怎么看"（路由+5维），
执行层负责"怎么动"（仓位+止栓），
