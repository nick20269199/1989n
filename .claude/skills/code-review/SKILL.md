# Code Review

> 在任何代码改动合入前，系统性地过一遍**逻辑正确性、边界条件、回归影响**。

## 通用 Review 清单

### 逻辑正确性
- [ ] 条件判断有没有漏分支？(if-elif 缺 else？)
- [ ] 循环边界对不对？(off-by-one？空集合？)
- [ ] 错误处理有没有吞异常？(except: pass？)

### 边界条件
- [ ] 输入为空/None/零值 → 是否崩溃？
- [ ] API/数据库返回异常格式 → 是否校验？
- [ ] 文件不存在/权限不足 → 是否优雅处理？
- [ ] 并发调用（定时任务重叠）→ 是否互斥？

### 回归风险
- [ ] 改了 A 但 B 依赖 A 的行为 → B 测了吗？
- [ ] 输出的格式/字段名变了 → 下游解析器兼容？
- [ ] 新增依赖 → 定时任务环境是否安装了？

## 项目专属：股票分析

### 数据管道 Review

**数据源变更（如 API 切换）：**
- [ ] 新 API 返回字段名和旧 API 是否一致？
- [ ] 新 API 的限流/频率限制？
- [ ] 字段值为 0 或空字符串时的业务含义？(涨停数=0 vs 数据未取到)
- [ ] 数据类型转换有没有丢精度？

**保鲜盾 (data_quality_gate.py)：**
- [ ] 阈值设置合理？(交易时段 vs 非交易时段不同)
- [ ] 过时数据的告警是否能到达飞书 alerts 群？
- [ ] freshness_check 结果被正确消费了？(不是只 log 不阻断)

### 飞书输出 Review

- [ ] 消息标题不会太长/含换行？
- [ ] emoji 是否必要？
- [ ] 多群路由正确？(分析→main, 告警→alerts)
- [ ] 消息内容含敏感信息？

### 多 Agent 管线 Review

- [ ] Expert1-5 的输出被 grader 评分了？
- [ ] 评分低于阈值的输出是否被阻断？
- [ ] Lead 的重试循环有最大次数限制？

## Review 流程

```
1. git diff 看改了什么
2. 对照清单逐项检查
3. 发现问题 → 判断类型：
   - 🐛 逻辑错误 → 必须修
   - ⚠ 边界未处理 → 视严重度决定
   - 📦 回归风险 → 标注回归测试位置
4. 输出 review 结果，按严重度排序
```
