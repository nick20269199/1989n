# 上下文健康监控 (Context Health)

> **核心原则**: 不要在 Claude 开始"失忆"后才清上下文。提前预警，主动清理。

## 触发时机

**手动触发**:
- 用户输入 `/ctx-health`
- 用户说"是不是上下文太长了"、"又开始乱答了"

**自动检测** (Claude 应在以下模式出现时主动提醒):
- 同一问题修了 2 轮还在原地打转 → 上下文已污染
- Claude 开始忘记对话开头提到的约束/文件 → 上下文溢出
- 当前对话超过 30 轮来回 → 接近常规上下文预算的 70%
- 用户反复重复同一个要求 → Claude 已"失聪"

## 健康评分

Claude 在检测到上述模式时，给出快速评分：

```
=== 上下文健康 ===
轮次: ~XX 轮
状态: 🟢 健康 / 🟡 注意 / 🔴 建议清理
建议: [一句话]
```

### 状态阈值

| 状态 | 轮次估算 | 行为 |
|------|---------|------|
| 🟢 健康 | <20 轮 | 正常推理 |
| 🟡 注意 | 20-35 轮 | 考虑 `/compact` |
| 🔴 建议清理 | >35 轮 | 建议 `/clear` 重开 |

## 应对策略

### `/compact` — 压缩保留
- 保留关键决策、当前任务目标、已修改的文件路径
- 丢弃中间推理过程、已解决的子问题
- 适用: 话题未完但上下文太长

### `/clear` — 完全清空
- 新任务开始前
- 同一问题修 2 轮还在打转
- 切换到完全不相关的任务

### 重开后的正确姿势
```
"之前我们在做 [X]，现在的问题是 [Y]，相关文件是 [Z]，上次你给的方案是 [A] 但 [B] 不对"
```
一句话重建上下文，不要从头叙述。

## 反模式

- ❌ 感觉 Claude 开始糊涂了，继续加轮次"纠正"它 → 越纠越乱
- ❌ 明明已经修了 3 轮，还在坚持不 `/clear` → 浪费时间
- ❌ `/clear` 后重新叙述 10 分钟的背景 → 一句话重建即可
