# 每周认知审计 v2 (Weekly Audit)

> 5 条 v2 压缩摘要 = 一周的认知轨迹。审计不只是找重复错误，还要检查凝练的规则是否有效、框架是否自欺。

## 执行步骤

### Step 1: 加载本周数据

```bash
ls -t D:/1989n/stock_data/learning/daily_digest_*.json | head -5
```

逐一读取本周 v2 日摘要。同时读：
- `stock_data/learning/rules.json` — 本周凝练的规则
- `stock_data/learning/ratio_baselines.json` — 本周比率快照
- `stock_data/learning/forecast_tracker.json` — 预测准确率
- `stock_data/learning/efficiency_daily.json` — 效率趋势

**v3 新增**: 同时运行:
```bash
python stock_analysis/rule_verifier.py --report
python stock_analysis/forecast_closer.py --report
```

### Step 2: 三轨健康度评分

对每条轨打分（1-10）：

**理解力轨**：
- 周期判定一致性：本周5天的系统判定阶段是否一致？是否反复跳变？
  - 5天一致=3分，跳变≤1次=2分，跳变≥2次=0分
- 预期差转化为验证假设的比例？
  - 有预期差并生成假设=3分，有预期差但未转化=1分，无预期差分析=0分
- 问题推进：关闭/推进了几个问题？(0个=0分, 1个=2分, 2+=4分)

**创造力轨**：
- 比率警报转化率：触发了几次警报？其中几次生成了深度研究？
  - 有警报且有研究=3分，有警报无研究=1分，无警报=0分
- 凝练转化率：本周几条认知增益被凝练为可执行规则？
  - ≥3条=4分, 1-2条=2分, 0条=0分
- 新角度：有没有提出用户/市场没想到的新视角？(+3分)

**效率轨**：
- 工具有效率趋势（本周 vs 上周）
- 凝练规则中 `is_condensed: true` 的比例（≥60%=3分, 30-60%=2分, <30%=0分）
- 重复搜索/无效调用次数趋势

### Step 3: 规则有效性审计（v3 强化）

检查本周凝练的每条规则：
1. 规则的适用条件是否在当前周期阶段被满足？
2. 如果条件满足 → 规则是否被实际执行？
3. 如果执行了 → 结果是否正确？（由 rule_verifier 自动判定）
4. `is_condensed` = false 的规则为什么不达标？缺少哪个字段？

**v3 新增 — 规则回测结果**:
从 `rule_verifier --report` 的输出中提取：
- 本周有多少条规则的条件实际被触发了？
- 触发后规则给出的行动是否正确？（准确率）
- 是否有规则被自动标记为退役？原因是什么？

产出规则审计表：
| 规则ID | 条件 | 动作 | 凝练 | 触发 | 回测准确 | 状态 |
|--------|------|------|------|------|---------|------|

对 `is_condensed = false` 且连续 2 周未改进的规则，标记为"滞留印象"。
对准确率 < 50% 且已触发 ≥3 次的规则，标记为"需修正或退役"。

### Step 4: 重复错误检测

扫描本周所有日摘要中的 `self_check.mistake` 和 `self_check.mistake_root_cause` 字段：
- 同一个错误模式出现 ≥2 次 → 标记为系统性问题
- 错误根因分布统计：知识盲区 / 逻辑跳跃 / 惯性输出 / 数据缺失 / 情绪干扰
- 对比上周：哪种错误类型在减少？哪种在增加？

### Step 5: Ego Death 检查（新）

这是 v2 最关键的新增环节。

检查本周每份日摘要的 `self_check.ego_challenge` 字段：

1. **本周有几天的 ego_challenge 不为空？**
   - 0 天 = 本周没有证据挑战核心假设 → 标注"框架可能处于自循环验证状态"
   - 1-2 天 = 正常
   - 3+ 天 = 框架可能正在经历重构

2. **用户本周纠正了几次？纠正分类：**
   - 框架问题（我的认知框架本身有缺陷）
   - 数据问题（我用了错误/过时的数据）
   - 执行问题（我知道但对但没做到）
   - 如果框架问题占比 ≥30% → 框架本身需要修正

3. **本周我是否对某个高度自信的判断被证明是错的？**
   - 如果是 → 这个错误是否被充分分析了？还是被轻描淡写地放过了？

4. **反躬自问**：
   - 本周我的分析中是否存在"惯性输出"（没查数据就下判断）？
   - 本周我是否回避了某个让我不舒服的相反证据？
   - 本周我最大的认知盲区在哪？（不是"不知道什么数据"，而是"不知道自己不理解什么机制"）

### Step 6: 产出审计报告

写入 `stock_data/learning/weekly_audit_YYYYMMDD.md`：

```markdown
# 周审计报告 v3 YYYY-MM-DD ~ YYYY-MM-DD

## 三轨健康度
| 轨道 | 得分 | 关键指标 |
|------|------|---------|
| 理解力 | X/10 | 周期一致性X, 预期差→假设X/N, 问题关闭X个 |
| 创造力 | X/10 | 警报转化X/N, 凝练规则X条, 新角度X个 |
| 效率 | X/10 | 有效率X%, 凝练达标率X% |

## 规则审计（含回测）
- 本周凝练规则: N条（达标 M条, 未达标 K条）
- 本周触发规则: T条, 回测准确率: X%
- 自动退役规则: N条（原因）
- 滞留印象（连续2周未凝练）: L条

## 预测追踪（v3 新增）
- 总预测数: N, 已验证: M, 准确率: X%
- 本周到期预测: N条（应验: M条, 未应验: K条）
- 准确率趋势 vs 上周: ↑/↓/→
- 若准确率 < 40%: 触发"研究框架修正"信号

## 重复错误
- [错误模式]: 出现N次, 根因: X, 趋势: ↑/↓/→

## Ego Death 检查
- 本周 ego_challenge 天数: N/5
- 用户纠正次数: N, 其中框架问题: K次 (占比 X%)
- 最大认知盲区: [具体描述]
- 自我评分: 本周我的分析是否存在惯性输出/回避反证？ [是/否, 说明]

## 框架修正建议
- [基于以上分析的修改建议]
```

## 约束

- 如果本周日摘要 < 3 条，审计照常但标注"数据不足"
- ego_challenge 为空不意味着"没有问题"，意味着"没有发现问题的机制"
- 审计报告 ≤800 字
- 如果是月末最后一周的审计，额外做月总结：本月最核心的5条凝练规则、最严重的3个重复错误、认知框架的最大变化
