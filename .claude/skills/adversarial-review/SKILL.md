# 交易对抗审查 (Adversarial Review)

> **铁律**: 这不是确认你的判断，而是试图推翻它。推翻不了的判断才有资格被执行。

## 触发时机

**必须触发**:
- 开仓决策前（任何 Buy 信号）
- 加仓决策前
- 止损位调整前
- 大仓位操作前（单票仓位 >20%）

**建议触发**:
- 连续盈利后（警惕过度自信）
- 连续亏损后（警惕报复交易）
- 重大消息面冲击时

## 认知环注入 (v2)

**在执行五路审查之前，必须先加载以下上下文**:

```python
from daily_compress import judge_cycle_stage, load_json, RATIO_BASELINES_FILE, RULES_FILE

# 1. 周期阶段
market = _read_market_data()
cycle = judge_cycle_stage(market)
# → 当前阶段 + 策略 + 下一阶段风险

# 2. 比率警报
ratio_data = load_json(RATIO_BASELINES_FILE)
entries = ratio_data.get("entries", [])
alerts = []
if entries:
    latest = entries[-1]
    for name, info in latest.get("ratios", {}).items():
        if info.get("alert") == "triggered":
            alerts.append({"ratio": name, "z_score": info.get("z_score", 0)})

# 3. 规则库
rules_data = load_json(RULES_FILE)
active_rules = [r for r in rules_data.get("rules", [])
                if r.get("status") not in ("retired", "stale")]
```

**注入到审查材料中**:
```markdown
## 市场环境（审查必须参考）

**当前周期**: {stage} ({confidence})
**策略约束**: {strategy_hint} — 当前阶段策略
**下一阶段风险**: {next_stage_risk}
**活跃比率警报**: {alert_summary} — 如果有警报，该交易的方向是否与警报方向冲突？
**规则库**: {len(active_rules)} 条活跃规则 — 历史上类似模式是否有沉淀？
```

**如果无法获取数据（非交易日等），标注为"认知环数据缺失"但不跳过审查。**

## 五路对抗角色

每个角色收到同样的交易 thesis + 数据，但从不同角度攻击：

| 角色 | 攻击角度 | 核心问题 |
|------|---------|---------|
| **空方代言人** | 做空逻辑 | "如果这是笔烂交易，最可能的死法是什么？" |
| **风控守门人** | 纪律合规 | "止损位合理吗？仓位会不会爆？哪条铁律被踩了？" |
| **数据鉴证官** | 数据可信度 | "这个数据来源有没有问题？有没有 cherry-pick？" |
| **认知偏差猎手** | 心理偏差 | "你在给自己找什么理由？锚定效应？确认偏差？" |
| **历史镜鉴者** | 历史对比 | "上次类似的判断对吗？这个标的上次你错在哪？" |

## 工作流

### Step 1: 准备审查材料

向子 agent 提供:
- 交易 thesis（1-2 句核心逻辑）
- 关键数据（价格/资金/题材/消息/情绪 — 五维度）
- 当前持仓状态
- 本次操作的止损位和仓位

**不给子 agent 的东西**: 你的结论、你的置信度、你的六问自检结果 — 这些会污染它们的独立判断。

### Step 2: 五路并行攻击

同时启动 5 个 subagent（`subagent_type="general-purpose"`），每个只带角色指令 + 审查材料。

**空方代言人 prompt**:
```
你是一个做空交易员，专门找多头的逻辑漏洞。
以下是某个交易员的做多 thesis 和数据。你的任务是：

1. 找到 thesis 中最脆弱的假设，给出做空的核心理由（2-3条）
2. 指出多头可能忽略的负面信号
3. 评估：如果这个交易失败，最可能的死法是什么？

**市场环境约束**:
- 当前处于{stage}阶段，策略是"{strategy}"
- 如果市场正处于高潮→衰退转换，做多信号的可信度应大幅降低
- 如果有比率警报（{alerts_summary}），判断这些警报是否与你的做空逻辑一致

不要折中，不要给"中性"意见。你就是空方。

输出格式：
- 做空核心理由：
- 被忽略的负面信号：
- 周期阶段冲突（如果有）：
- 最可能的死法：
```

**风控守门人 prompt**:
```
你是一个风控总监，不关心能不能赚钱，只关心会不会亏死。
以下是某个交易员的交易计划。对照以下铁律逐一检查：

铁律清单：
R1: 止损位是否明确？距当前价多远？是否合理？
R2: 数据来源是否可追溯？
R3: 结论是否标注置信度+反面可能性+触发修正条件？
R4: 是否检查过与该标的历史分析的关联/矛盾？
R5: 单票仓位是否超标？总仓位是否过重？
R6: 六问自检是否跑完？
R7: 超大单方向是否与决策方向矛盾？

**周期阶段约束**:
- 当前市场处于"{stage}"阶段（{confidence}）
- 该阶段的策略是：{strategy}
- 检查：这次操作是否符合当前阶段的策略？
  - 高潮阶段禁止加仓追高
  - 衰退阶段禁止开新仓
  - 冰点阶段仅允许左侧试探性仓位（≤5%）

操作红线：
- 禁止亏损补仓
- 禁止利好当日追高
- 逆向加仓四条件是否全部满足？

输出格式：
- 违反的铁律编号及具体内容：
- 周期阶段冲突（如果有）：
- 仓位风险（单票%/总仓位%）：
- 止损位合理性评估：
- 风控结论（通过/有条件通过/否决）：
```

**数据鉴证官 prompt**:
```
你是一个数据审计师，只关心数据的真实性、完整性和代表性。
以下是某个交易员的分析数据。逐一检查：

1. 每条数据是否有明确来源（财联社/东方财富/新浪/StockAPI）？
2. 是否存在挑选有利数据、忽略不利数据的情况？
3. 关键数据是否有时效性问题？
4. 不同数据源之间是否有矛盾？如果有，以哪个为准？
5. 技术指标计算是否正确？（均线/RSI/MACD/成交量）

输出格式：
- 数据来源可信度评估：
- 疑似 cherry-pick 的数据点：
- 数据矛盾/时效性问题：
- 审计结论（通过/有瑕疵/不可信）：
```

**认知偏差猎手 prompt**:
```
你是一个行为金融学专家，专门检测交易决策中的认知偏差。
以下是某个交易员的 thesis 和数据。扫描以下偏差：

- 确认偏差：是否先有结论再找证据？
- 锚定效应：是否被某个价格/事件锚定了？
- 过度自信：连续盈利后是否放松了标准？
- 损失厌恶：是否因为不想承认亏损而坚持？
- 近期偏差：是否过度放大最近的信息？
- 控制幻觉：是否以为"持仓=控制"？
- 羊群效应：是否因为别人都在做所以做？

对照 R6 六问自检清单：
1. 反面证据被认真考虑了吗？
2. cherry-picking 的可能性能排除吗？
3. 止损位是被迫设的还是认真算的？
4. 和历史哪个判断最像？那次对了还是错了？
5. 置信度有没有被锚定？
6. 如果错了，能认错吗？

输出格式：
- 检测到的偏差（名称+证据）：
- 六问自检中可能被跳过的项：
- 情绪状态评估（冷静/中性/兴奋/恐惧）：
- 偏差结论（无偏差/有偏差但可控/严重偏差需暂停）：
```

**历史镜鉴者 prompt**:
```
你是一个交易复盘专家，专门通过历史对比防止重复犯错。
以下是某个交易员的当前 thesis 和相关历史记录。

任务：
1. 找到与当前标的/当前模式最相似的历史交易判断
2. 对比：那次判断对了还是错了？如果错了，原因是什么？
3. 当前 thesis 是否重复了某个历史错误模式？
4. R4 进化沉淀：这次的判断如果对了/错了，分别应该沉淀什么规则？
5. **规则库检查**：规则库中有{active_rules_count}条活跃规则，有没有与当前交易模式匹配的历史规则？这些规则的验证准确率是多少？

**周期阶段约束**:
- 当前处于"{stage}"阶段
- 如果规则库中有在此阶段被验证过的规则，优先参考

输出格式：
- 最相似的历史判断（时间+标的+结论）：
- 历史结果（对/错，原因）：
- 当前 thesis 是否在重复历史错误：
- 匹配的规则库规则（如果有）：
- 可沉淀的进化规则：
```

### Step 3: 五路合成判决

收到 5 个子 agent 的输出后，按下述规则合成：

**不民主原则**: 不是投票多数决。一个角色的致命发现就可以否决一笔交易。

**合成规则**:
1. 风控守门人否决 → 直接 NO-GO，不用看其他四个
2. 数据鉴证官判"不可信" → 暂停交易，先修数据
3. 空方代言人 + 认知偏差猎手同时亮红灯 → 极高概率问题交易
4. 历史镜鉴者发现重复错误模式 → 降级置信度至少一档
5. **周期阶段否决**: 如果操作方向与当前周期阶段策略矛盾（如衰退阶段开仓、高潮阶段加仓）→ 自动降级至 MODIFY，需要额外证据才能 GO
6. **比率警报否决**: 如果活跃比率警报方向与操作方向矛盾 → 需在判决书中明确说明为何逆警报操作
7. 五路全绿 → 可以执行，但仍保留最低 5% 的反面概率

### Step 4: 输出判决书

```markdown
## 对抗审查判决书

**审查对象**: [标的代码+名称] [操作类型: 开仓/加仓/减仓/清仓]
**审查时间**: [时间]
**市场环境**: {stage}阶段 ({confidence}), 策略:{strategy}

### 五路裁决

| 角色 | 结论 | 关键理由 |
|------|------|---------|
| 空方代言人 | ✅/⚠️/❌ | 一句话 |
| 风控守门人 | ✅/⚠️/❌ | 一句话 |
| 数据鉴证官 | ✅/⚠️/❌ | 一句话 |
| 认知偏差猎手 | ✅/⚠️/❌ | 一句话 |
| 历史镜鉴者 | ✅/⚠️/❌ | 一句话 |

### 周期阶段评估
- 当前阶段: {stage}
- 操作与阶段匹配: 符合/偏离/背离
- 阶段风险: {next_stage_risk}

### 比率警报评估
- 活跃警报: [列表]
- 与操作方向是否冲突: 是/否

### 致命发现
[如果有角色 veto，写清楚为什么]

### 置信度修正
- 原始置信度: __%
- 修正后置信度: __%
- 修正原因: __

### 最终判决
- **执行**: GO / NO-GO / MODIFY
- **若 MODIFY**: 需要修改什么
- **若 NO-GO**: 什么条件满足后可以重新考虑
```

## 与现有机制的关系

| 机制 | 职责 |
|------|------|
| R6 六问自检 | 内部自查 — 你自己问自己 |
| **对抗审查（本技能）** | 外部攻击 — 五个角色从不同角度推翻你 |
| R4 进化沉淀 | 事后验证 — 48h 后检验判断对错 |

## 反模式

- ❌ 先有结论再跑审查（审查 = 橡皮图章）
- ❌ 风控否决后还试图"说服"风控
- ❌ 跳过低置信度角色的警告
- ❌ 把审查当做"走流程"而不是真正的挑战
- ❌ 在情绪激动时跳过审查
