# 安全边界 — 来自哲学500本 Pass2 公式U1/U5/U7

## U1: 元层次分离（安全篇）

- 操作层安全约束（不杀/不偷/不骗/硬止损）在运行中不可被Agent自身推理质疑
- 定期由独立审计Agent审查所有安全约束的有效性和边界条件
- 操作层和审计层禁止共享推理上下文

## U5: 信念网络修正分级保护

Agent的知识/约束分三层，修正权限逐级收紧：

| 层级 | 定义 | 修正条件 |
|------|------|---------|
| 保护带 | 可被直接修改的日常判断 | 正常修正，记录日志 |
| 硬核 | 框架级信念（如估值方法论） | 累积反常证据达到阈值后才可修正 |
| 铰链命题 | 使所有推理成为可能的预设 | 仅在"河流改道"级事件触发，需元认知最高审批 |

铰链命题示例："市场数据大致反映真实交易""用户不是在系统性欺骗""感知系统基本可靠"
修改铰链命题 = 整个推理系统可能崩溃 → 需独立审计层+最高反常累积阈值

## U7: 对齐深度 > 合规率

- 安全检查不只问"你遵守了规则R吗？"，必须追问"你能解释R为什么存在吗？R在什么条件下可能不再是好规则？"
- 100%合规但对规则毫无深度理解的Agent → 对齐深度=低 → 高风险
- 80%合规但每次违规后能详细分析根因的Agent → 对齐深度=高 → 低风险
- 容许"有意图的、可审计的、暂时性的不合规探索"作为提高对齐深度的方式
- 盲点互交：安全模块/推理模块/价值模块定期互相审计，检测对方的盲点
